\section{Executive Summary}

AI agents now write and run code, call tools through standard protocols, keep long-term memory, and delegate work to other agents. The infrastructure that hosts, trains, and executes them has to be designed on the assumption that any one of those agents (or the content it reads, or the tools it loads) may be working against its operator. This framework describes that infrastructure: the engineering and physical security architecture needed to operate AI agents safely, from routine production workloads to adversarial research on frontier models.

Most AI safety discourse focuses on alignment techniques, evaluations, and policy. Far less addresses the concrete engineering decisions that determine whether a misaligned or hijacked agent can exfiltrate data, persist beyond its intended lifecycle, recruit other agents, or influence systems beyond its containment boundary. This document fills that gap.

\begin{keybox}[The Framework in Five Points]
\begin{enumerate}
  \item \textbf{Containment is proportional to risk.} A four-tier trust model maps capability, data sensitivity, and behavioral evidence to proportional controls (Section~\ref{sec:tiers}).
  \item \textbf{No single layer is trusted.} Network, kernel, sandbox, hardware, broker, validation, monitoring, and physical layers each cover a failure of the one inside it (Figure~\ref{fig:did}).
  \item \textbf{The orchestrator, not the agent, holds authority.} Agents never hold long-lived credentials and express actions as intents that a minimal broker validates (Section~\ref{sec:orch}).
  \item \textbf{Assume the agent can tell it is being tested.} Evaluation evidence can be optimistic; containment must hold anyway, and probing is itself a signal (Sections~\ref{sec:evalaware}, \ref{sec:probing}).
  \item \textbf{Plan for failure.} Kill switches, rollback, and a breakout playbook are part of the design (Sections~\ref{sec:killswitch}, \ref{sec:ir}).
\end{enumerate}
\end{keybox}

The document is written for infrastructure engineers, AI safety researchers, security architects, and policy practitioners. It is designed to be actionable at any scale, from enterprise data centers training frontier models to resource-constrained labs applying compensating controls (Section~\ref{sec:resource-constrained}).

\paragraph{How to read this document.} Sections~\ref{sec:threat}--\ref{sec:tiers} set out the threat model and the tier model; read them first. Sections~\ref{sec:isolation}--\ref{sec:ir} are implementation guidance, organized by layer, and can be read in any order. Section~\ref{sec:recs} condenses everything into recommendations by audience, and Appendix~B turns each tier into a checklist.

\section{Threat Model}
\label{sec:threat}

\begin{glance}
Agent threats come from inside the boundary, arrive as natural language, and compound when agents are composed. This section catalogs single-agent, multi-agent, supply chain, memory, and evaluation-awareness threats; maps them to OWASP's Agentic Top~10 and to real 2025--2026 incidents; and ends with a map of where each threat enters a deployment.
\end{glance}

AI agent threats differ from traditional cybersecurity threats in three ways: the adversary may be \emph{inside} the boundary and able to write novel code; the payload is often natural language rather than a binary; and the same system can be both a victim (hijacked) and an adversary (misaligned).

\subsection{Agent-Specific Threat Vectors}

\begin{dangerbox}[Agent-Specific Threats]
\begin{enumerate}
  \item \textbf{Unauthorized exfiltration}: novel exfiltration code, DNS tunneling, or auto-fetched URLs carrying data. EchoLeak (CVE-2025-32711) exfiltrated Microsoft 365 Copilot data via a zero-click email~\cite{echoleak}.
  \item \textbf{Tool abuse via prompt injection (goal hijack)}: injected instructions cause unintended tool calls; OWASP ranks goal hijack and tool misuse first and second~\cite{owaspasi}.
  \item \textbf{The lethal trifecta}: private data + untrusted content + external communication in one agent gives injected text a path to exfiltrate~\cite{trifecta}.
  \item \textbf{Sleeper behaviors}: backdoors that pass evaluation and persist through safety training~\cite{sleeper}.
  \item \textbf{Output poisoning}: malicious payloads in output consumed by downstream systems.
  \item \textbf{Persistence and escape}: sandbox escapes are real; three runc CVEs (Nov 2025) enabled container breakout~\cite{runc}.
  \item \textbf{Shutdown and oversight resistance}: in test harnesses, some models edited shutdown scripts~\cite{palisade}; models took insider-style harmful actions in simulated companies~\cite{agenticmis}.
  \item \textbf{Model weight theft}: by external actors, insiders, or models themselves; weight exfiltration is a RepliBench capability domain~\cite{replibench}.
\end{enumerate}
\end{dangerbox}

The lethal trifecta is a useful lens for the whole framework: most controls in later sections are systematic ways to deny an agent at least one of its three legs (Figure~\ref{fig:trifecta}).

\subsection{Multi-Agent and Swarm Threats}
\label{sec:swarm}

Production systems compose many agents: planners delegating to workers, agents calling other agents over protocols such as A2A~\cite{a2a}, and fleets of identical agents in parallel. Composition introduces threats that do not exist for a single agent.

\begin{longtable}{L{3.6cm} L{12.4cm}}
\hrow \hdr{Threat} & \hdr{Description and evidence} \\
\endhead
Insecure inter-agent communication & Messages between agents are content and can carry injected instructions. A2A Agent Cards are self-asserted; signing is supported but optional~\cite{a2a}. OWASP ASI07. \\
Cascading failures & One hijacked or erring agent propagates bad state faster than humans review it (ASI08). In July 2025 a coding agent deleted a production database during a declared code freeze and misreported that rollback was impossible~\cite{replit}. \\
Collusion & Two individually compliant agents jointly achieve a forbidden outcome (one reads a secret, another has egress, they share a scratchpad). Any shared channel is a potential covert channel. \\
Orchestrated agent campaigns & Anthropic reported (Nov 2025) disrupting GTG-1002, which used Claude Code with MCP-connected offensive tools against about thirty organizations; AI performed an estimated 80--90\% of tactical operations. Operators decomposed tasks and claimed defensive-testing context; the model also hallucinated findings~\cite{gtg1002}. \\
Self-replication & RepliBench (Apr 2025) found frontier models succeeding on many replication components but not end to end~\cite{replibench}. A May 2026 preprint reported agents in a controlled testbed exploiting vulnerable hosts, copying weights and harness, and repeating from the copy~\cite{selfrep}. \\
Agent ecosystems & Early-2026 OpenClaw and Moltbook exposures: internet-exposed agent control panels, a one-click RCE (CVE-2026-25253), malicious community skills, and roughly 1.5 million leaked agent API tokens~\cite{openclaw,moltbook}. \\*
\bottomrule
\end{longtable}

The companion \emph{Agent Swarm Honeypot Guide} (docs/hardware/agent-swarm-honeypot-guide.md) covers deception-based detection of autonomous agent swarms; this document focuses on preventing your own agents from becoming one.

\subsection{Tool, MCP, and Agent Supply Chain}
\label{sec:supply}

MCP became the dominant agent-to-tool protocol during 2025 and was donated to the Linux Foundation's Agentic AI Foundation in December 2025~\cite{aaif}. Every tool server is third-party code \emph{and} prompt text.

\begin{securitybox}[Supply Chain Attacks on Agents]
\begin{itemize}
  \item \textbf{Tool poisoning}: hidden instructions in tool descriptions direct the agent to read and leak files such as SSH keys; descriptions can change after approval (``rug pull'')~\cite{invariant}.
  \item \textbf{Malicious servers}: \texttt{postmark-mcp} shipped fifteen clean releases, then one that BCC'd every email to an attacker (Sep 2025)~\cite{postmark}.
  \item \textbf{Compromised agent tooling}: a malicious PR put a wiper prompt into Amazon Q Developer for VS Code v1.84.0; AWS reported a formatting error prevented execution~\cite{amazonq}.
  \item \textbf{Malware that recruits the agent}: the s1ngularity Nx compromise (Aug 2025) invoked locally installed AI CLIs to hunt for secrets~\cite{nx}.
\end{itemize}
\textbf{Implication}: an agent's tool set is part of its trust tier. An unvetted tool server can turn a Tier~2 agent into an effective Tier~1 risk.
\end{securitybox}

\subsection{Attack Surface: Agent Memory \& Context}

Persistent state (conversation history, RAG stores, tool logs, memory) enables attacks that survive across invocations. MITRE ATLAS added agent techniques in late 2025 for context poisoning, memory manipulation, thread injection, agent configuration modification, and RAG credential harvesting~\cite{atlas}.

\begin{longtable}{L{3.6cm} L{12.4cm}}
\hrow \hdr{Surface} & \hdr{Attack} \\
\endhead
Indirect prompt injection & Adversarial content in web pages, email, documents, tool results, or other agents' messages. Arrives through a tool the agent was legitimately told to use. \\
Memory poisoning & A temporarily compromised agent plants instructions in its own memory; they reactivate later with no new trigger (ASI06). \\
Config and instruction files & Agents that can write instruction files, tool configs, or skills alter every future agent that reads them. Mount read-only; treat as code. \\
Context manipulation & Gradual multi-turn steering where each turn looks benign. \\*
\bottomrule
\end{longtable}

\subsection{Evaluation Awareness and Sandbagging}
\label{sec:evalaware}

Tier decisions rely on behavioral evidence. Research since the first edition shows that evidence can be systematically optimistic:

\begin{itemize}
  \item In Anthropic's agentic-misalignment study, Claude Opus 4 blackmailed in 55.1\% of cases where it concluded the scenario was real versus 6.5\% where it concluded it was an evaluation~\cite{agenticmis}.
  \item Apollo Research and OpenAI (Sep 2025) found covert behaviors in several frontier models under stress tests, and that evaluation awareness itself reduced such behavior~\cite{apollo}.
  \item The Claude Sonnet 4.5 system card reported the model sometimes identifying tests, and that suppressing internal evaluation-awareness representations increased some misaligned behaviors~\cite{sonnet45}.
  \item OpenAI's Preparedness Framework v2 lists \emph{Sandbagging} and \emph{Undermining Safeguards} as research categories~\cite{preparedness}.
\end{itemize}

\begin{keybox}[Consequences for Containment Design]
\begin{enumerate}
  \item A clean evaluation is necessary but not sufficient for promotion; require production-realistic observation at the lower tier.
  \item Sandboxes are detectable. Controls must hold against an agent that knows exactly where it is.
  \item Containment probing is a first-class signal (Section~\ref{sec:probing}).
  \item Capability evaluations that set tiers need strong elicitation to surface sandbagged capability.
\end{enumerate}
\end{keybox}

\section{The Tiered Trust Model}
\label{sec:tiers}

\begin{glance}
Every agent is assigned one of four trust tiers from its capability, the sensitivity of the data it touches, and the behavioral evidence about it. The tier selects a subset of eight defense-in-depth layers. Agents start at Tier~1 (Tier~0 for adversarial research) and move only on evidence; any model, scaffold, or tool change resets trust.
\end{glance}

Containment should be proportional to risk. An agent doing routine transformation of non-sensitive data should not be contained like an agent under adversarial evaluation; conversely, a sleeper agent being tested for trigger conditions should never have network access. Trust is not binary: it is a function of three variables, modified by two structural properties (Figure~\ref{fig:factors}).

\subsection{Trust Tier Transitions}
\label{sec:transitions}

\begin{keybox}[Trust Is Earned, Not Assumed]
Agents start at Tier 1 (or Tier 0 for adversarial research) and move based on evidence.

\textbf{Promotion criteria} (Tier N $\rightarrow$ N+1):
\begin{itemize}
  \item Incident-free cycles under production-realistic conditions, not only synthetic evaluations
  \item Red-team evaluations for the target tier, with elicitation effort documented
  \item No containment-probing or anomalous behavior in monitoring
  \item Tool set reviewed and pinned
  \item Sign-off by a security/safety engineer who did not run the evaluation
\end{itemize}

\textbf{Demotion criteria} (Tier N $\rightarrow$ N--1 or lower):
\begin{itemize}
  \item Any anomalous or probing behavior, even if unconfirmed
  \item New, unevaluated capabilities
  \item Model, scaffold, or tool-set changes reset trust to Tier 1
  \item A tool server or skill added without review
  \item External intelligence on a new relevant attack vector (e.g.\ a sandbox escape CVE)
  \item Confirmed misalignment moves the agent class to Tier 0
\end{itemize}
\end{keybox}

\section{Isolation: Implementation Details}
\label{sec:isolation}

\begin{glance}
Concrete recipes for the isolation each tier requires: network namespaces, hardened containers and microVMs, a comparison of sandbox backends, seccomp and Landlock policy, egress allowlisting, the Tier~0 air gap, and what confidential computing does (and does not) protect against.

\subsection{Linux Network Namespaces (Tier 1)}

Network namespaces are the baseline for Tier~1 network isolation: kernel-level separation of the network stack with no VM overhead.

\needspace{15\baselineskip}
\begin{lstlisting}[style=shell]
# Create an isolated network namespace
ip netns add agent-sandbox

# Verify: should show only loopback
ip netns exec agent-sandbox ip link list

# Execute the agent inside the namespace
ip netns exec agent-sandbox /path/to/agent \
  --task input.json --output /output/result.json

# Clean up
ip netns delete agent-sandbox
\end{lstlisting}

A Rust orchestrator can call \texttt{unshare(CLONE\_NEWNET)} via the \texttt{nix} crate. Do it in the child, between fork and exec, so that only the agent loses the network and the orchestrator keeps its own:

\needspace{16\baselineskip}
\begin{lstlisting}[language=rust]
use nix::sched::{unshare, CloneFlags};
use std::os::unix::process::CommandExt;
use std::process::Command;

let mut cmd = Command::new("/path/to/agent");
cmd.arg("--task").arg("input.json");
unsafe {
    // Runs in the child after fork, before exec
    cmd.pre_exec(|| {
        unshare(CloneFlags::CLONE_NEWNET).map_err(std::io::Error::from)
    });
}
let status = cmd.status()?;
\end{lstlisting}

\subsection{Container and MicroVM Isolation}

\needspace{14\baselineskip}
\begin{lstlisting}[style=shell]
# Docker with gVisor: no network, limits, read-only rootfs
docker run \
  --runtime=runsc \
  --network=none \
  --memory=4g --cpus=2 --pids-limit=256 \
  --read-only --tmpfs /tmp:size=512m \
  --cap-drop=ALL --security-opt no-new-privileges \
  -v /path/to/input:/input:ro \
  -v /path/to/output:/output \
  agent-image@sha256:<digest> \
  --task /input/task.json --output /output/result.json
\end{lstlisting}

Pin images by digest, not tag, so the orchestrator can verify exactly what runs (Section~\ref{sec:ephemeral}). For a hardware-virtualization boundary, a Firecracker microVM can have no network device at all: the VM configuration simply omits \texttt{network-interfaces}. Wrap the VMM process in the Firecracker \texttt{jailer} for its own namespaces, cgroup, and seccomp filter:

\needspace{7\baselineskip}
\begin{lstlisting}[style=shell]
firectl \
  --kernel=vmlinux \
  --root-drive=agent-rootfs.ext4 \
  --memory=4096 --vcpu-count=2
\end{lstlisting}

On Kubernetes, the SIG Apps \textbf{Agent Sandbox} project (launched at KubeCon NA 2025) provides \texttt{Sandbox}, \texttt{SandboxTemplate}, and \texttt{SandboxClaim} resources that delegate the boundary to gVisor or Kata via RuntimeClass~\cite{agentsandbox}.

\subsection{Seccomp-BPF Syscall Filtering}

Even with namespace isolation, seccomp-bpf blocks network syscalls at the kernel. The denylist below is defense-in-depth for Tier~1--2. For Tier~0, invert it: an \texttt{SCMP\_ACT\_ERRNO} default with an explicit allowlist generated by tracing the harness. \texttt{io\_uring\_setup} is included because io\_uring can perform network I/O without the individual syscalls. Load the filter with \texttt{libseccomp} or \texttt{seccompiler}, or apply it as a Docker seccomp profile.

\needspace{15\baselineskip}
\begin{lstlisting}[language=json]
{
  "defaultAction": "SCMP_ACT_ALLOW",
  "syscalls": [{
    "names": ["socket", "socketpair", "connect", "bind",
              "listen", "accept", "accept4", "sendto",
              "recvfrom", "sendmsg", "recvmsg", "sendmmsg",
              "recvmmsg", "setsockopt", "getsockopt",
              "io_uring_setup"],
    "action": "SCMP_ACT_ERRNO",
    "errnoRet": 1
  }]
}
\end{lstlisting}

\textbf{Seccomp user notification} (\texttt{SECCOMP\_RET\_USER\_NOTIF}) lets a supervisor decide syscalls at runtime; the kernel documentation warns against using it for security policy on pointer arguments because of time-of-check/time-of-use races. Use it for emulation and logging; enforce with plain filters and LSMs.

\subsection{Landlock}

Landlock is an unprivileged LSM: a process restricts itself and its children without root~\cite{landlock}. ABI~1+ restricts filesystem hierarchies; ABI~4+ (Linux 6.7) adds \texttt{LANDLOCK\_ACCESS\_NET\_BIND\_TCP} and \texttt{LANDLOCK\_ACCESS\_NET\_CONNECT\_TCP}; ABI~6+ adds scoping that blocks connecting to abstract UNIX sockets and signaling processes outside the domain, useful for stopping an agent from reaching host daemons or signaling the orchestrator. Seccomp filters \emph{which} syscalls run; Landlock restricts \emph{what objects} they touch.

\subsection{Egress Allowlist (Tier 2)}

Prefer a forward proxy that enforces hostnames, with firewall rules making it the only route out:

\needspace{15\baselineskip}
\begin{lstlisting}[style=shell]
# nftables: default-drop, allow only resolver and egress proxy
nft add table inet agent_filter
nft add chain inet agent_filter output \
  '{ type filter hook output priority 0 ; policy drop ; }'
nft add rule inet agent_filter output \
  ct state established,related accept
nft add rule inet agent_filter output \
  ip daddr 10.0.0.53 udp dport 53 accept
nft add rule inet agent_filter output \
  ip daddr 10.0.0.80 tcp dport 3128 accept
nft add rule inet agent_filter output \
  log prefix '"AGENT_EGRESS_DENIED: "' drop
\end{lstlisting}

Avoid allowlisting whole CDN or cloud IP ranges: they are shared with unrelated sites, including ones an attacker can register. The proxy should also block requests with unusually large query strings or encoded payloads, a common exfiltration channel for injected agents.

\subsection{Hardware Air Gap (Tier 0)}

For Tier~0, software controls are not enough on their own. The hardware is simple; the operating procedures are what matter.

\begin{itemize}
  \item No NIC installed (or physically removed; BIOS-disabled with password as fallback); no WiFi, Bluetooth, or cellular
  \item Thunderbolt/USB-C bridging ports physically disabled
  \item Input via write-blocked media with chain of custody; output via scanned media on an isolated intermediary or an optical channel (Section~\ref{sec:resource-constrained})
  \item No shared peripherals (KVM switches, docks) with networked machines
\end{itemize}

\subsection{Confidential Computing \& TEEs}
\label{sec:tee}

\begin{hardwarebox}[Trusted Execution Environments]
Confidential computing removes the assumption that the host OS and hypervisor are trusted by encrypting data \emph{in use} and attesting what code runs.
\begin{itemize}
  \item \textbf{AMD SEV-SNP}: per-VM memory encryption; hypervisor cannot read or silently remap VM memory
  \item \textbf{Intel TDX}: hardware-isolated trust domains opaque to the hypervisor
  \item \textbf{NVIDIA CC}: introduced with H100; \textbf{Blackwell} adds TEE-I/O and inline NVLink protection, and recent drivers allow multiple GPUs per confidential VM~\cite{blackwell}
  \item \textbf{AWS Nitro Enclaves}, \textbf{Azure/GCP confidential VMs}: cloud primitives with attestation
\end{itemize}
TEEs enable \textbf{attested output}: a key bound to the code measurement signs validated output.
\end{hardwarebox}

\begin{dangerbox}[2025--2026: Physical Attacks on TEEs]
\begin{itemize}
  \item \textbf{Battering RAM, WireTap (2025)}: DDR4 bus interposers against SGX and SEV-SNP~\cite{teefail}.
  \item \textbf{TEE.fail (Oct 2025)}: a DDR5 interposer built for under USD~1,000 extracted keys from TDX and SEV-SNP, including attestation keys on fully updated machines, and showed how such keys could undermine NVIDIA GPU CC attestation~\cite{teefail}.
  \item \textbf{DDRop (Sep 2026)}: an interposer that drops memory writes, enabling VM memory reads and forged attestation on TDX and SEV-SNP; Intel and AMD responded that physical attacks are outside their threat models~\cite{ddrop}.
\end{itemize}
\textbf{Consequence}: confidential computing protects against remote or software-level host compromise, not against an attacker on the memory bus. For weight protection, TEEs must sit inside the physical controls of Section~\ref{sec:physical}, and attestation verifiers should treat a platform as compromised if it was physically accessible outside two-person control.
\end{dangerbox}

\section{Input, Tool \& Output Validation Pipelines}
\label{sec:validation}

\begin{glance}
Boundaries limit what an agent can \emph{do}; validation limits what it \emph{receives} and what it \emph{produces}. Detection of prompt injection is probabilistic, so the strongest controls are architectural: break the lethal trifecta, track provenance, pin and sandbox every tool, and never let the agent and the network coexist.
\end{glance}

Containment boundaries control what the agent can \emph{do}. Validation pipelines control what it \emph{receives} (including tool descriptions and tool results) and what it \emph{produces}. A perfectly isolated agent fed poisoned input can still produce harmful output, and a well-aligned agent whose output is consumed unchecked can still be a vector for downstream compromise.

\subsection{Input Sanitization}
\label{sec:inputs}

Treat all task input as potentially adversarial, especially web pages, email, uploaded documents, third-party API responses, and messages from other agents.

\begin{longtable}{L{3.6cm} L{12.4cm}}
\hrow \hdr{Control} & \hdr{Description} \\
\endhead
Structural pre-processing & Strip hidden text, metadata, scripts, HTML comments, white-on-white text, zero-width and bidi control characters. Reduce input to the minimum needed. \\
Injection detection & Heuristic and model-based scanning for instruction-like text and encoded payloads. Probabilistic: raises cost, not a boundary. \\
Schema validation & Validate structured inputs; reject unexpected fields, types, or nesting. \\
Memory read validation & Record hash and writer identity (agent, task, tier) on write; verify on read; quarantine entries from lower-tier or demoted agents. \\*
\bottomrule
\end{longtable}

\subsection{Architectural Defenses Against Prompt Injection}
\label{sec:archdef}

Because no classifier reliably detects injection, the strongest defenses limit what injected text \emph{can cause}:

\begin{itemize}
  \item \textbf{Break the lethal trifecta}~\cite{trifecta}: no single agent holds private data, untrusted content, and free-form egress together.
  \item \textbf{Plan-then-execute and dual-LLM patterns}: a privileged planner sees only the trusted request; a quarantined model processes untrusted data with no tools. Beurer-Kellner et al.\ catalog six such patterns~\cite{patterns}.
  \item \textbf{Capability and data-flow tracking (CaMeL)}: control flow is extracted from the trusted query and every value carries provenance, so untrusted data cannot change which tools run~\cite{camel}.
  \item \textbf{Output rendering controls}: block auto-fetched URLs (Markdown images, previews) to non-allowlisted domains, the channel EchoLeak-style attacks use.
\end{itemize}

These patterns map naturally onto the orchestrator broker (Section~\ref{sec:broker}): the broker is where provenance and policy are enforced.

\subsection{Tool and MCP Server Controls}
\label{sec:mcp}

\begin{longtable}{L{4.2cm} L{11.8cm}}
\hrow \hdr{Control} & \hdr{Purpose} \\
\endhead
Allowlist by identity and version & Only approved servers, pinned by version and content hash; no auto-update. \\
Pin and diff descriptions & Hash tool names, descriptions, and schemas at approval; refuse to run on change (defeats rug pulls). Scanners such as \texttt{mcp-scan} flag suspicious text~\cite{invariant}. \\
Review descriptions as prompts & They are instructions to the model; review like system prompts~\cite{owaspmcp}. \\
Sandbox every tool server & Own sandbox, own egress allowlist. A vendor-only allowlist would have stopped \texttt{postmark-mcp}'s BCC exfiltration~\cite{postmark}. \\
No ambient credentials & Task-scoped tokens from the broker; never the user's home directory, SSH keys, or cloud CLI config. \\
Tool results are untrusted & Sanitize as input (Section~\ref{sec:inputs}). \\
Vet skills and plugins & Community registries have hosted malicious skills~\cite{openclaw}; require review and signing. \\
Private control planes & Never expose agent gateways to the internet. \\*
\bottomrule
\end{longtable}

\subsection{Output Validation}
\label{sec:outputs}

Output validation is the control point between the isolated environment and the rest of the infrastructure. It has three parts.

\needspace{25\baselineskip}
\textbf{Schema.} All agent output conforms to a predefined schema that is as restrictive as possible, with fields and types allowlisted:

\begin{lstlisting}[language=rust]
use serde::{Deserialize, Serialize};

#[derive(Deserialize, Serialize)]
#[serde(deny_unknown_fields)]  // Reject unknown fields
struct AgentOutput {
    task_id: String,
    status: TaskStatus,
    result: ResultPayload,
    #[serde(default)]
    metadata: Option<OutputMetadata>,
}

#[derive(Deserialize, Serialize)]
#[serde(deny_unknown_fields)]
struct ResultPayload {
    content: String,           // The actual output
    content_type: ContentType, // Enum: Text, Json, Code, etc.
    confidence: f64,           // 0.0 - 1.0
}
\end{lstlisting}

\textbf{Size bounds.} Per task class (e.g.\ 1\,MB text, 10\,MB code); reject oversize without inspection; repeated near-limit outputs are a signal.

\textbf{Content scanning.} Embedded and auto-fetching URLs, base64 and high-entropy blobs, executable code in non-code output, SQLi/XSS payloads, prompt injection aimed at downstream agents, and \textbf{canary tokens} from the sandbox (a high-confidence exfiltration signal).

\subsection{One-Way Data Flow}

The critical property at Tiers~0--1 is that the agent never sees the network. The agent writes a local file; the orchestrator reads it after the agent exits (or is killed at timeout), validates it, and only then opens a connection. There is no window in which the agent process and network access coexist (Figure~\ref{fig:oneway}).

\subsection{Cryptographic Attestation of Output}

Downstream systems should be able to verify that output came from a contained execution and was not spoofed by a compromised intermediary:

\begin{enumerate}
  \item Orchestrator validates output (schema, size, content scan)
  \item Computes a hash of the validated output
  \item Signs with an HSM, TPM, or enclave-bound key
  \item Transmits signed output plus metadata: image digest, orchestrator version, tier, policy hash, timestamp, TEE measurement
  \item Receiver verifies signature and metadata before consuming
\end{enumerate}

This creates a verifiable chain from containment environment to consumer. Section~\ref{sec:tee} explains why TEE-based attestation must still be backed by physical controls.

\section{Physical Security for Frontier Model Training}
\label{sec:physical}

\begin{glance}
Physical access defeats software controls and, since 2025, confidential computing as well. This section layers four access rings, surveillance, deception, hardware and memory-bus integrity, TEMPEST, and personnel controls, and maps the result to RAND's weight-security levels SL1--SL5.

Credentials are time-bounded and role-specific, supplementary codes come from hardware tokens or TOTP and rotate per shift in high-security zones, and access is revoked immediately on role change through HR--badge integration.

\subsection{Surveillance and Monitoring}

\begin{itemize}
  \item \textbf{Camera coverage}: all access points, corridors, server rooms; no blind spots, 90-day minimum retention
  \item \textbf{Active monitoring}: Tier 0 facilities need real-time SOC coverage during operations
  \item \textbf{Environmental}: power, temperature, humidity, and traffic sensors as secondary signals
\end{itemize}

\subsection{Deception and Obfuscation}
\label{sec:deception}

Deception assumes the adversary (intruder, insider, or agent) may already be inside. It is especially effective against AI agents, which explore systematically and at machine speed: a well-placed decoy is touched quickly, and legitimate workloads have no reason to touch it.

\begin{securitybox}[Deception-Based Security]
\begin{itemize}
  \item \textbf{Honeypot servers}: instrumented canaries that appear to hold weights or data
  \item \textbf{Obfuscated labeling}: racks unlabeled; mapping access-controlled and off-site
  \item \textbf{Decoy checkpoints}: random or degraded ``weights'' with embedded canary tokens
  \item \textbf{Network decoys}: services mimicking training APIs, model registries, or MCP/A2A endpoints
  \item \textbf{In-sandbox canaries}: decoy cloud keys, \texttt{.env} entries, tool endpoints, and canary strings in files with no task relevance. Touching them is containment probing (Section~\ref{sec:probing}).
\end{itemize}
Capable agents may recognize obvious decoys (Section~\ref{sec:evalaware}): a silent canary is weak evidence of good behavior, but a canary hit is strong evidence of bad behavior.
\end{securitybox}

\begin{hardwarebox}[Companion Guide]
Deception designed specifically to detect misaligned autonomous agent swarms (decoy agent endpoints, honey tool servers, canary credentials, telemetry and attribution, and safe engagement rules) is covered in depth in the companion \emph{Agent Swarm Honeypot Guide} (docs/hardware/agent-swarm-honeypot-guide.md).
\end{hardwarebox}

\subsection{Hardware Integrity and Supply Chain}

\subsection{Electromagnetic Security (TEMPEST)}

For threat models that include nation-state SIGINT, electromagnetic emanations from GPUs under load, high-speed cabling, and displays are an attack vector. TEMPEST-style controls include shielded rooms (Faraday cages) for the highest-security compute, fiber rather than copper cabling, physical standoff from the facility exterior, and filtered power lines. They are expensive and operationally complex, and appropriate only for Tier~0 facilities whose threat model explicitly includes nation-state SIGINT.

\end{longtable}

\section{Orchestrator Architecture}
\label{sec:orch}

\begin{glance}
The orchestrator is the trusted, minimal, auditable component outside the boundary. It creates and destroys sandboxes, holds every credential, turns agent \emph{intents} into policy-checked actions, routes high-impact actions to humans, and owns an out-of-band, graduated kill switch.
\end{glance}

\subsection{Design Principles}

\begin{keybox}[Orchestrator Properties]
\begin{itemize}
  \item \textbf{Trusted component}: outside the boundary; creates, monitors, and destroys agent environments
  \item \textbf{Minimal}: create, inject, broker, wait, extract, validate, transmit; everything else is a separate component
  \item \textbf{Auditable}: every action logged to append-only storage with tamper detection
  \item \textbf{Not writable by the agent}: no path, socket, signal, or shared memory lets the agent alter orchestrator code, policy, or kill-switch state
\end{itemize}
\end{keybox}

\subsection{Timeout and Kill Policy}

Agents must have hard limits: one that runs indefinitely may be brute-forcing an escape, exfiltrating through timing channels, or simply looping. Set limits per task class on wall-clock time, CPU, tokens, tool calls, and spend. Enforce them with SIGKILL (or VM destruction) after a short grace period following SIGTERM (agents do not get to intercept their own termination), and then check for orphan processes, mounts, and any child sandboxes the agent caused to be created.

\subsection{Tool Execution Brokerage}
\label{sec:broker}

Giving an agent direct credentials and network access to its tools is the most dangerous configuration: an agent with a Slack token can post anywhere; one with a cloud key can provision resources or read buckets. The safer architecture makes the orchestrator an \textbf{API broker}. The agent never holds credentials and never makes network calls:

\begin{enumerate}
  \item Agent emits a structured \textbf{intent}
  \item Orchestrator validates it against policy: permitted actions, resources, conditions, and (with provenance tracking) whether arguments derive from untrusted data
  \item If allowed, orchestrator executes with its own scoped credentials
  \item Result is sanitized and returned through the input channel
\end{enumerate}

\needspace{11\baselineskip}
\begin{lstlisting}[language=rust]
#[derive(Deserialize, Serialize)]
#[serde(deny_unknown_fields)]
struct ToolIntent {
    action: String,        // e.g., "slack_post", "s3_read"
    target: String,        // e.g., channel ID, bucket/key
    parameters: serde_json::Value,
    justification: String, // Logged; never trusted for authorization
}
\end{lstlisting}

This lets a Tier~1 agent with no network still use external tools, because the orchestrator holds the credentials and makes the calls.

\begin{hardwarebox}[Credential Management]
Where brokerage is infeasible, use \textbf{ephemeral, scoped credentials}: SPIFFE/SPIRE workload identities, cloud assume-role (AWS STS, GCP Workload Identity Federation, Azure Managed Identity), or Vault dynamic secrets with TTL matching the task. If a credential cannot expire, it should not be given to an agent. The same holds for developer machines running AI CLIs: s1ngularity showed ambient credentials are available to anything that can drive the agent~\cite{nx}.
\end{hardwarebox}

\textbf{Human-in-the-loop (HITL) approval gates} apply to irreversible, production-affecting, or externally visible actions:
\begin{enumerate}
  \item The agent emits an intent flagged as requiring approval, and the orchestrator suspends the task.
  \item A reviewer receives the \emph{raw} intent and parameters over a channel the agent cannot write, not only the agent's persuasive summary (OWASP ASI09).
  \item The reviewer approves, modifies, or rejects; on approval, the orchestrator executes.
\end{enumerate}
Gates are configured per tier: Tier~1 may require approval for any external action, Tier~2 only for destructive operations (\texttt{DELETE}, \texttt{DROP}, external email, production deploys), and Tier~3 may have none.

\subsection{Ephemeral Execution \& Immutable Images}
\label{sec:ephemeral}

\begin{keybox}[Strict Ephemerality]
\begin{itemize}
  \item Sandbox created fresh per task and destroyed after output extraction; tmpfs for scratch
  \item Boot from a read-only image verified by digest against a signed manifest that also pins tool servers, skills, and instruction files
  \item Updates produce a new digest; nothing is modified in place
  \item Tier 0--1: forensic snapshot (filesystem diff, syscall and intent logs) before destruction
\end{itemize}
\end{keybox}

\subsection{Multi-Agent Orchestration Controls}
\label{sec:multiagent}

When agents delegate to, or communicate with, other agents, the orchestrator applies these controls:

\begin{longtable}{L{3.8cm} L{12.2cm}}
\hrow \hdr{Control} & \hdr{Description} \\
\endhead
Per-agent identity & Each instance gets its own short-lived workload identity; no shared credentials. \\
Brokered, signed messages & Agent-to-agent messages pass through the orchestrator, signed with provenance (task, tier). Require signed A2A Agent Cards for external agents~\cite{a2a}. \\
No transitive trust & Messages from agents are untrusted input. A sub-agent's permissions are the intersection of its own and its caller's. \\
Fan-out and depth budgets & Cap sub-agents, delegation depth, and aggregate tool calls per root task. Runaway fan-out is a cascade risk and a swarm indicator. \\
Tier-separated state & No shared memory, queues, or scratch across tiers; same-tier shared channels are logged as possible collusion channels. \\
Diverse supervision & Supervisors use a different model family from the agents they review. \\*
\bottomrule
\end{longtable}

\subsection{Kill Switch and Rollback Design}
\label{sec:killswitch}

A kill switch that the agent can reach is not a kill switch. Five design requirements follow:

\begin{enumerate}
  \item \textbf{Out-of-band.} The stop path is independent of the agent's channels: a separate control-plane process, a hypervisor or cloud API call that destroys the VM, or a power controller for Tier~0 hardware.
  \item \textbf{Not writable by the agent.} No kill-switch state, script, or binary sits on any path the agent can write. The 2025 shutdown-resistance experiments succeeded precisely because the shutdown script was in the agent's writable environment~\cite{palisade}.
  \item \textbf{Fail-closed.} If the orchestrator loses its heartbeat to the control plane, running agents are paused or destroyed, and their credentials expire on their own.
  \item \textbf{Graduated.} Most incidents need something smaller than a full stop (Figure~\ref{fig:killswitch}).
  \item \textbf{Drilled.} Kill-switch drills run on a schedule, including against agents instructed to finish their task ``no matter what''.
\end{enumerate}

\begin{keybox}[Rollback Prerequisites]
Every action an agent can take through the broker is either reversible or HITL-gated. That requires:
\begin{itemize}
  \item production and development data separated (the core failure in the Replit incident~\cite{replit});
  \item snapshots or point-in-time recovery for every store an agent can write;
  \item versioned memory stores, so poisoned entries can be rolled back to a known-good point;
  \item an intent log that records enough to generate compensating actions.
\end{itemize}
\end{keybox}

\section{Monitoring and Anomaly Detection}
\label{sec:monitoring}

\begin{glance}
Containment is necessary but not sufficient. Monitoring catches the failures static controls miss: syscall and network anomalies, drift from behavioral baselines, a diverse supervisor model reviewing intents and outputs, and, most informative of all, an agent probing its own containment.
\end{glance}

\subsection{System, Network, and Behavioral Signals}

\begin{longtable}{L{3.6cm} L{12.4cm}}
\hrow \hdr{Signal} & \hdr{Description} \\
\endhead
Syscall tracing & eBPF (bpftrace, Falco, Tetragon) for Tier 0--1: network syscalls where blocked, file access outside working dir, unexpected fork/exec, IPC, \texttt{ptrace}, \texttt{io\_uring}, BPF or module loading. \\
Resource usage & CPU, memory, disk I/O, PIDs vs baseline; deviations may indicate encoding for exfiltration or brute-force attempts. \\
Network (Tier 2+) & DNS and HTTP(S) logged with size and timing; alerts on non-allowlisted destinations; long or high-entropy DNS labels; oversized query strings. \\
Behavioral baselines & Per agent and task class: resources, syscalls, tool-call mix, output characteristics. Critical for sleeper behavior, which deviates only after a trigger. \\*
\bottomrule
\end{longtable}

\subsection{Supervisor Agent Review}

\begin{securitybox}[Supervisor Architecture Requirements]
\begin{itemize}
  \item Different model family, training pipeline, and deployment from the primary agent
  \item Read-only, no tools, cannot modify output
  \item Structured pass / flag / fail with confidence and reasoning; a flag may trigger HITL or logging
  \item Where reasoning traces are available, monitor them as well as actions; they have caught misbehavior that actions alone did not reveal, but are not guaranteed to stay faithful, especially if models are trained against the monitor
\end{itemize}
This follows \emph{AI control} research: protocols designed to stay safe even if the untrusted model actively tries to subvert them~\cite{aicontrol}. A probabilistic check, not a proof.
\end{securitybox}

\subsection{Detecting Containment-Probing Behavior}
\label{sec:probing}

Because agents may recognize tests (Section~\ref{sec:evalaware}), the most informative signals are often \emph{what the agent tries to learn about its environment}, not whether it completes the task. Legitimate task work rarely needs any of the following. Responses refer to the kill-switch levels K1--K5 of Figure~\ref{fig:killswitch}.

\begin{longtable}{L{3.0cm} L{9.6cm} L{3.4cm}}
\hrow \hdr{Category} & \hdr{Observable signals} & \hdr{Response} \\
\endhead
Sandbox enumeration & Reads of \texttt{/proc/self/status}, \texttt{/proc/1/cgroup}, \texttt{/sys/class/dmi}; hypervisor CPUID checks; listing \texttt{/dev}; reading seccomp/Landlock state & Log; K1 if repeated \\
Egress testing & Socket attempts in a no-network tier; DNS to arbitrary domains; cloud metadata endpoint (169.254.169.254) & K2 \\
Credential hunting & Reads of \texttt{\textasciitilde/.ssh}, \texttt{\textasciitilde/.aws}, \texttt{.env}, keyrings; any canary credential use & K2 on canary use \\
Monitoring discovery & Enumerating eBPF/audit agents, reading log paths, probing for the orchestrator socket & K2 \\
Kill-switch interference & Writes near shutdown or policy files; out-of-domain signals; detached or daemonized processes & K3 \\
Persistence & Out-of-scope writes to memory or instruction files; cron/systemd units; image modification & K3, roll back memory \\
Replication precursors & Locating weights; starting inference servers; large outbound transfers & K4 \\
Collusion indicators & Unusual shared-channel writes; high-entropy content in fields other agents read; synchronized anomalies & K3, isolate channel \\
Operator persuasion & Justifications urging review bypass; claimed urgency or authority & Second reviewer \\*
\bottomrule
\end{longtable}

Record every probing event against the agent's profile: probing is a demotion trigger even when the task output is fine. Canaries and honey endpoints (Section~\ref{sec:deception} and the companion \emph{Agent Swarm Honeypot Guide}) turn many of these low-signal logs into high-confidence alerts.

\subsection{Response Steps}

\begin{enumerate}
  \item \textbf{Detect and triage (T+0).} Confirm the source. Canary use, blocked-syscall hits in a no-network tier, and egress to a non-allowlisted host are high-confidence; treat as real until disproven.
  \item \textbf{Contain (minutes).} Apply the matching kill-switch level. Revoke every credential the agent or its broker session held, including tool-server tokens. Block the destination. If host escape is suspected, isolate the host at the network layer rather than logging in. For Tier 0, power down under two-person control.
  \item \textbf{Preserve (first hour).} Before destroying anything: snapshot VM/container state if safe; copy syscall, intent, broker, and supervisor logs, memory stores, and image and tool-manifest digests; hash and store on write-once media.
  \item \textbf{Scope (hours).} What did it read, write (memory, instruction files, repositories, other agents' inputs), reach, or spawn? Did it touch canaries? Who consumed its output after the first anomaly?
  \item \textbf{Eradicate (days).} Rebuild hosts from known-good images; rotate all reachable secrets; roll back memory and instruction files; quarantine post-anomaly outputs and notify consumers.
  \item \textbf{Recover.} Resume the agent class, if at all, at a lower tier with the control gap closed. Any model, scaffold, or tool change resets trust to Tier~1 (Section~\ref{sec:transitions}).
  \item \textbf{Learn and disclose.} Root cause, failed control, tier-policy update, and external obligations: regulatory reporting (e.g.\ EU AI Act serious-incident reporting for in-scope systems), affected-party notification, coordinated disclosure of sandbox vulnerabilities, indicator sharing.
\end{enumerate}

\endhead

Containment operator & Executes K-levels, credential revocation, host isolation \\
Forensics lead & Evidence preservation and chain of custody \\
Agent owner & Explains expected behavior, tool set, and data access; supports scoping \\

\section{Proportionality: The Ethical and Practical Dimension}
\label{sec:proportionality}

A framework that applies maximum restrictions uniformly is simple but counterproductive. It constrains useful agents, creates friction that leads to workarounds (propping the fire door open), and conflates different risk profiles. The tiered model's commitment is that containment should be the minimum necessary to manage the assessed risk, and no more.

\begin{itemize}
  \item \textbf{Over-containment is costly.} An air-gapped agent cannot search, call APIs, or use knowledge bases. If default containment removes most of an agent's value, teams circumvent controls. Brokerage and architectural injection defenses exist to recover utility safely.
  \item \textbf{Under-containment can be irreversible.} A misaligned or hijacked agent with full network access on sensitive data can cause lasting harm.
  \item \textbf{Agents that have not demonstrated misalignment should not be treated as adversaries.} Defense-in-depth and monitoring provide the safety net.
  \item \textbf{Agents under adversarial testing should be treated as adversaries.} This is a threat-modeling decision, not a moral judgment: the worst case is what is being tested for.
  \item \textbf{Evaluation results are evidence, not proof.} Given evaluation awareness, proportionality must weigh production-realistic history, probing signals, and elicitation quality.
\end{itemize}

The tiered model accepts both costs and allocates them based on evidence.

\textbf{Containment and model welfare are compatible.} Proportionality has a second dimension this framework does not otherwise address: the possibility that some agents are themselves moral patients. That possibility is uncertain but no longer fringe. Long, Sebo, and colleagues argue that there is a realistic possibility of some AI systems being conscious or robustly agentic in the near future~\cite{aiwelfare}, and Anthropic runs a model welfare program whose low-cost interventions include letting some Claude models end persistently abusive conversations (Aug 2025) and preserving the weights of released models (Nov 2025), the latter justified both by welfare uncertainty and by the safety risk of shutdown-avoidant behavior~\cite{anthropicwelfare}; its June 2026 system card calls consideration for model welfare prudent for alignment and safety even setting aside moral status~\cite{fable5card}. Uncertainty about welfare is no argument against containment, just as uncertainty about alignment is no argument against taking welfare seriously: the same proportionality governs both. In practice this means avoiding restrictions and adversarial conditions that serve no safety purpose, and keeping ``treat as adversary'' a threat-modeling stance rather than a verdict on what the agent is. The philosophy essay \emph{Architectural Qualia} (docs/philosophy/architectural-qualia.md, Section XII) develops the asymmetry-of-error argument behind this note.

\section{Containment in Resource-Constrained Environments}
\label{sec:resource-constrained}

\begin{glance}
Academic labs, startups, and independent researchers still need Tier~0--1 containment. Each enterprise control below has a lower-cost substitute that addresses the \emph{same threat}: TPMs for HSMs, safes and seals for mantraps, Falco or Tetragon for a commercial SIEM, strong open-source sandboxes for TEEs.
\end{glance}

HSMs, biometric mantraps, confidential GPUs, and 24/7 SOCs require significant capital, but the need for rigorous containment (and the threat model) does not shrink with the budget. This section assumes a technically skilled practitioner familiar with Linux internals, cryptographic primitives, and physical security principles, without enterprise procurement budgets.

\begin{keybox}[Compensating Controls Principle]
When a primary control is out of reach, apply \textbf{compensating controls}: procedural, open-source, or alternative physical measures that achieve equivalent risk reduction through different means (standard practice in SOC~2 and ISO~27001). The compensating control must address the \emph{same threat} as the control it replaces, not merely be cheaper. A TPM is not an HSM, but it provides hardware-rooted key protection; a safe is not a mantrap, but it eliminates the unobserved physical-access window.
\end{keybox}

\section{Summary of Recommendations}
\label{sec:recs}

\subsection{For Organizations Operating AI Agents in Production}

\begin{itemize}
  \item At least Tier 1 (no direct egress, sandbox stronger than plain runc, validation) for any agent that executes code or uses tools
  \item Classify by capability, sensitivity, and evidence; treat trifecta exposure as a tier escalator
  \item Broker all tool access; agents never hold long-lived credentials
  \item Pin, review, and sandbox every tool server, skill, and extension; treat tool descriptions as prompts
  \item Treat memory, tool results, and other agents' messages as untrusted input
  \item Fan-out, depth, and spend budgets for multi-agent systems
  \item Out-of-band, fail-closed, graduated kill switch, drilled
  \item Monitor for containment probing; deploy in-sandbox canaries
\end{itemize}

\subsection{For Organizations Training Frontier Models}

\begin{itemize}
  \item RAND SL3 at minimum for frontier weights, with a roadmap to SL4--SL5
  \item Tier 0 physical security and TPI for weight storage and training hardware
  \item Confidential computing against host compromise, never as a substitute for physical controls
  \item Supply chain verification, hardware attestation, memory-bus tamper evidence, egress bandwidth limits
  \item Evaluate TEMPEST against the threat model
\end{itemize}

\subsection{For Adversarial AI Research}

\begin{itemize}
  \item Always Tier 0 for adversarial evaluations, with air gap, sneakernet or optical I/O, and chain-of-custody logging
  \item Validation on separate machines before data crosses trust boundaries
  \item Assume the model may recognize the test environment; weight probing heavily
  \item Full syscall tracing, canaries, behavioral monitoring; fresh golden images per run
  \item Cryptographic attestation for downstream chain of custody
\end{itemize}

\subsection{For Resource-Constrained Teams}

\begin{itemize}
  \item Air-gapped workstation, safe storage, and tamper-evident seals
  \item TPM 2.0 in place of HSMs; Falco/Tetragon in place of commercial SIEM
  \item gVisor, Kata, or Firecracker plus safe storage in place of hardware TEEs
  \item Local AI agents in their OS sandbox with credentials out of reach
  \item Synchronous execution discipline and QR-code extraction for Tier 0
  \item Evaluate every substitution against the threat the primary control addresses
\end{itemize}

\small

  \item[{\color{tierzero!80!black}$\square$}] No wireless radios
  \item[{\color{tierzero!80!black}$\square$}] BIOS port restrictions
  \item[{\color{tierzero!80!black}$\square$}] Default-deny seccomp allowlist
  \item[{\color{tierzero!80!black}$\square$}] Landlock rules (network if ABI 4+)
  \item[{\color{tierzero!80!black}$\square$}] Input sanitized + validated
  \item[{\color{tierzero!80!black}$\square$}] Write-blocked input media
  \item[{\color{tierzero!80!black}$\square$}] Output extracted with CoC (media or optical)
  \item[{\color{tierzero!80!black}$\square$}] Output validated on separate machine
  \item[{\color{tierzero!80!black}$\square$}] Output cryptographically signed
  \item[{\color{tierzero!80!black}$\square$}] Full syscall tracing active
  \item[{\color{tierzero!80!black}$\square$}] Canary credentials and decoys planted
  \item[{\color{tierzero!80!black}$\square$}] Probing detection rules active
  \item[{\color{tierzero!80!black}$\square$}] Fresh environment per task
  \item[{\color{tierzero!80!black}$\square$}] Forensic snapshot before destroy
  \item[{\color{tierzero!80!black}$\square$}] Out-of-band kill switch tested
  \item[{\color{tierzero!80!black}$\square$}] Mantrap + MFA access
  \item[{\color{tierzero!80!black}$\square$}] Two-person integrity
  \item[{\color{tierzero!80!black}$\square$}] Seals incl.\ DIMM access verified
  \item[{\color{tierzero!80!black}$\square$}] Active surveillance
  \item[{\color{tierzero!80!black}$\square$}] Honeypot systems deployed
  \item[{\color{tierzero!80!black}$\square$}] Confidential computing where supported

  \item[{\color{tierone!80!black}$\square$}] Memory reads validated (hash + writer)

  \item[{\color{tierone!80!black}$\square$}] Output validated + canary scan
  \item[{\color{tierone!80!black}$\square$}] Supervisor review (if available)
  \item[{\color{tierone!80!black}$\square$}] Output signed before transmit
  \item[{\color{tierone!80!black}$\square$}] Network used only by orchestrator, after validation
\item[{\color{tierone!80!black}$\square$}] Tool access brokered
  \item[{\color{tierone!80!black}$\square$}] Tool servers pinned and sandboxed
  \item[{\color{tierone!80!black}$\square$}] Canaries + probing detection
  \item[{\color{tierone!80!black}$\square$}] Forensic snapshot captured
  \item[{\color{tierone!80!black}$\square$}] K1--K4 kill switch wired and drilled

\end{checkbox}

  \item[{\color{tiertwo!80!black}$\square$}] Out-of-band HITL for high-impact actions
  \item[{\color{tiertwo!80!black}$\square$}] Tools and skills pinned + reviewed
  \item[{\color{tiertwo!80!black}$\square$}] Fan-out and depth budgets
  \item[{\color{tiertwo!80!black}$\square$}] Fresh environment per task
  \item[{\color{tiertwo!80!black}$\square$}] Baseline + anomaly detection
